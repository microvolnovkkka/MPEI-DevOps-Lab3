# Экспорт событий в CSV

Лабораторная работа 3, вариант 10. На странице можно выбрать события в Москве, указать нужные столбцы и скачать их в заданном порядке. Данные поступают из [выданного API](https://github.com/nelkor/moscow-events), CSV формируется в браузере.

## Запуск

Понадобятся Git и работающий Docker с Compose и Buildx. Для первого запуска нужен интернет, чтобы скачать образы и зависимости. На Windows подойдёт Docker Desktop в режиме Linux-контейнеров.

```sh
git clone https://github.com/microvolnovkkka/MPEI-DevOps-Lab3.git
cd MPEI-DevOps-Lab3
docker compose up -d
```

Откройте [localhost:8082](http://localhost:8082) на компьютере с Docker или `http://IP_СЕРВЕРА:8082` с другого устройства в той же сети. При первом запуске PostgreSQL с PostGIS и Python API собираются из этого репозитория, а API добавляет в пустую базу примеры событий.

По умолчанию файл `.env` не нужен. Если порт 8082 занят, создайте рядом с `compose.yml` файл `.env` со строкой `HTTP_PORT=8083`, повторите `docker compose up -d` и откройте порт 8083.

## Как скачать CSV

1. Отметьте события в каталоге. Поиск и фильтры помогают их найти. Выбор сохраняется при переходе между страницами и виден во вкладке «Выбранные».
2. В разделе «Настройте файл» выберите столбцы и расставьте их стрелками. Укажите разделитель и нужны ли заголовки.
3. Сверьте первые три строки в предпросмотре и нажмите «Скачать CSV». В файл попадут все выбранные события. После обновления страницы выбор сбросится.

## Остановка и проверка

`docker compose stop` останавливает проект, `docker compose up -d` запускает его снова. Данные PostgreSQL хранятся в томе `postgres_data`. Состояние контейнеров показывает `docker compose ps -a`, причину ошибки запуска можно посмотреть через `docker compose logs --tail=50 db backend`.
