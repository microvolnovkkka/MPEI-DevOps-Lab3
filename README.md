# Лабораторная работа 3. Выгрузка событий в CSV

Индивидуальное задание №10: интерфейс для выгрузки выбранных событий в CSV-файл с настройкой состава и порядка столбцов.
[Issue с заданием](https://github.com/microvolnovkkka/MPEI-DevOps-Lab3/issues/1).

Фронтенд написан на HTML, CSS и JavaScript без фреймворков и сборщика.
Backend взят из [nelkor/moscow-events](https://github.com/nelkor/moscow-events), его код не изменяется.
Результат запускается командой `docker compose up -d`, как требуется в [условиях лабораторной](https://github.com/nelkor/MPEI-DevOps-Lab3).

## 1. Запуск

Нужны Git, работающий Docker, Buildx и Compose v2 или новее. Python и Node.js на хосте для запуска не нужны.
Первый запуск требует интернет: Docker получает исходники backend, базовые образы и зависимости.

Если на Ubuntu Docker установлен пакетами `docker.io` и `docker-compose-v2`, добавьте инструменты сборки и Git:

```bash
sudo apt update
sudo apt install -y git docker-buildx
sudo docker buildx version
```

В Docker Desktop на Mac Buildx уже есть. В Ubuntu это [пакет docker-buildx](https://packages.ubuntu.com/noble-updates/docker-buildx).

```bash
git clone https://github.com/microvolnovkkka/MPEI-DevOps-Lab3.git
cd MPEI-DevOps-Lab3
docker compose up -d
```

На Ubuntu при отсутствии доступа к Docker добавляйте `sudo`:

```bash
sudo docker compose up -d
sudo docker compose ps
```

Первый запуск занимает несколько минут из-за сборки. Дождитесь состояния `healthy` у трёх сервисов.

- На машине с Docker: http://localhost:8082
- С другого компьютера: `http://IP_СЕРВЕРА:8082`
- Узнать IP Ubuntu: `hostname -I`
- Готовность API: http://localhost:8082/health/ready
- Документация API: http://localhost:8082/docs

Привязывать аккаунт GitHub к Ubuntu для клонирования публичного репозитория по HTTPS не нужно.
Это учебный запуск в локальной сети; API преподавателя не имеет авторизации.

### Почему образы собираются

При проверке готовые образы `ghcr.io/nelkor/moscow-events:latest` и `postgis/postgis:17-3.6`
были доступны только для `linux/amd64`. У Ubuntu в UTM на Apple Silicon архитектура `arm64`.
Поэтому backend собирается из оригинального Dockerfile преподавателя, а база — из официального
`postgres:17-bookworm` с пакетами PostGIS 3.6. Эмуляция amd64 не нужна.
Такая конфигурация рассчитана также на обычные amd64-машины.

В адресе сборки закреплён коммит `157c5c86a7d2878adf5caccd742bb118e82f4482`:
Docker получает именно эту версию исходного кода. Зависимости Python устанавливаются по
оригинальному `pyproject.toml` преподавателя. Повторная сборка использует кэш Docker.

## 2. Пользование приложением

1. Откройте сайт. При необходимости задайте поиск по названию/описанию, категорию, статус и сортировку.
2. Отметьте события галочками. Галочка в заголовке выбирает **только текущую страницу**.
3. Переходите по страницам: выбор сохраняется. Вкладка «Выбранные» показывает весь выбор независимо от фильтров каталога.
   Поиск во вкладке «Выбранные» отключён.
4. В блоке «Настройте файл» снимите галочки с ненужных полей. Остальные поля доступны в «Добавить столбцы».
5. Стрелки ↑ и ↓ меняют порядок столбцов. «По умолчанию» восстанавливает исходные шесть полей.
6. Выберите разделитель: `;` (по умолчанию) или `,`. При необходимости отключите заголовки.
7. Проверьте первые три выбранных события в предпросмотре и нажмите «Скачать CSV».

В файл попадают **все выбранные события**, в том числе с других страниц и выбранные до смены фильтра.
Строки идут в порядке выбора, столбцы — в порядке, установленном стрелками.
Без событий или столбцов кнопка скачивания отключена.

Имя файла: `moscow-events-YYYY-MM-DD.csv`. Выбор и настройки хранятся в памяти страницы;
после её перезагрузки сбрасываются. Выгружаются данные, загруженные в браузер,
а не постоянная подписка на изменения базы.

### Формат CSV

- UTF-8 с BOM для распознавания кириллицы в Excel; переводы строк — CRLF.
- Все ячейки заключены в кавычки; кавычки внутри удваиваются. Разделители и переносы внутри текста сохраняются.
- Нулевая цена — `0`, отсутствующие значения — пустые ячейки.
- Даты сохраняются в формате API: ISO 8601 с часовым поясом. В таблице интерфейса даты показаны по Москве.
- Теги объединяются через ` | ` в одной ячейке.
- Текст, начинающийся как формула таблицы, получает апостроф для предотвращения выполнения формул из данных.
- Если Excel показывает всё в одном столбце: «Данные → Из текста/CSV», затем выбрать тот же разделитель.

## 3. Структура и логика проекта

```text
compose.yml                  — сервисы, порт, настройки и volume
docker/postgis/Dockerfile    — PostgreSQL 17 с PostGIS 3.6
nginx/default.conf          — выдача файлов и проксирование API
frontend/
  index.html                — таблица, фильтры, настройки экспорта
  styles.css                — оформление и адаптация к небольшим экранам
  app.js                    — состояние страницы и обработчики действий
  api.js                    — HTTP-запросы, параметры, ошибки и таймаут
  columns.js                — столбцы и извлечение значений из события
  csv.js                    — экранирование, создание CSV и скачивание
  favicon.svg               — значок вкладки
tests/export.test.js        — проверки CSV и формирования API-запроса
package.json               — только запуск тестов; npm-зависимостей нет
.env.example               — необязательные настройки
```

Копии backend в нашем репозитории нет: Docker получает его по ссылке из `build.context`.

```text
Браузер → Ubuntu:8082 → frontend (Nginx:80)
                          ├─ / → файлы из frontend/
                          └─ /api/v1/... → backend:8000 → db:5432
```

JavaScript выполняет `fetch('/api/v1/events?...')`. Nginx передаёт запрос backend и возвращает его JSON браузеру.
`include=venue,artist` добавляет данные площадки и исполнителя. API возвращает список страницами:
используются `page`, `page_size` и `meta.total`, без привязки к количеству демонстрационных записей.
Категории берутся из `/api/v1/meta/genres`; при недоступности справочника в CSV остаётся технический код категории.

Выбор хранится в `Map`: ключ — UUID, значение — событие. Это сохраняет порядок и не допускает дубликатов.
Список выбранных столбцов хранится отдельно как массив ID. Стрелки переставляют элементы этого массива.
Предпросмотр и CSV используют одну функцию `projectEvents`, поэтому порядок данных совпадает.
CSV создаётся как `Blob`, а временная ссылка с атрибутом `download` запускает скачивание.
Экспорт не изменяет сервер и базу.

## 4. Разбор compose.yml

`name: microvolnovkkka-lab3` задаёт отдельное имя проекта. Без него Compose берёт имя папки:
у разных студенческих форков оно может совпасть (`MPEI-DevOps-Lab3`), а вместе с ним совпадут имена сети и volume.
Теперь стандартное имя хранилища — `microvolnovkkka-lab3_postgres_data`.
Опция `-p` и переменная `COMPOSE_PROJECT_NAME` могут переопределить это имя.

`services` перечисляет контейнерные сервисы. Их имена `frontend`, `backend`, `db` доступны через DNS внутри сети Compose.
Сеть создаётся автоматически; на хост опубликован только Nginx. Backend и база доступны по внутренней сети.

| Настройка | Назначение |
| --- | --- |
| `image: nginx:stable-alpine` | Скачать готовый Nginx |
| `ports: "${HTTP_PORT:-8082}:80"` | Порт хоста → порт контейнера; по умолчанию 8082 |
| `./frontend:/usr/share/nginx/html:ro` | Подключить файлы сайта, только для чтения |
| `./nginx/default.conf:...:ro` | Подключить свой конфиг Nginx |
| `build.context: https://...git#...` | Собрать backend из указанного коммита |
| `build: ./docker/postgis` | Собрать базу по нашему Dockerfile |
| `environment` | Передать настройки внутрь контейнера |
| `depends_on` + `service_healthy` | Дождаться успешной проверки зависимости |
| `healthcheck` | Команда проверки работоспособности |
| `restart: unless-stopped` | Перезапуск после сбоя/перезапуска Docker, если сервис не остановлен вручную |
| `postgres_data:/var/lib/postgresql/data` | Хранить БД в именованном volume, сохраняющемся при пересоздании контейнера |

База получает `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`; backend — соответствующие
`PG_DB_NAME`, `PG_USER_NAME`, `PG_USER_PASSWORD`. Пароль в обоих сервисах берётся из одной переменной `DB_PASSWORD`.
Без `.env` используется учебное значение из Compose.
`PG_HOST=db` означает адрес базы внутри Docker. `localhost` в backend означал бы сам backend.

Порядок запуска: база успешно выполняет `SELECT 1` с настроенным пользователем и паролем → backend создаёт расширение, таблицы и seed →
встроенный healthcheck backend `/health/ready` проходит → запускается Nginx.
В проверке базы `PGPASSWORD` передаёт пароль клиенту `psql`, `PGCONNECT_TIMEOUT=3` ограничивает ожидание соединения.
`-h db` проверяет TCP-подключение через Docker-сеть. Локальное подключение через Unix-сокет или `127.0.0.1`
может использовать `trust` и не проверять пароль. `-w` запрещает интерактивный запрос пароля,
`ON_ERROR_STOP=1` требует завершить проверку с ошибкой при сбое SQL.
Знак `$$` передаёт `$` дальше в shell контейнера, без подстановки Compose.
Один `pg_isready` проверял бы только доступность сервера и мог бы вернуть успех даже при неправильных учётных данных.
`interval` — период проверки; `timeout` — время одной проверки; `retries` — число последовательных ошибок;
`start_period` — время на первоначальный запуск. Сам статус `unhealthy` не перезапускает процесс.

### Dockerfile базы

- `FROM postgres:17-bookworm` — официальный PostgreSQL 17 на Debian Bookworm.
- `RUN` — выполнить команды при сборке образа, а не при каждом запуске.
- `apt-get update` — получить список доступных пакетов внутри образа.
- `apt-get install -y --no-install-recommends` — установить пакеты без вопросов и необязательных рекомендаций.
- Два пакета PostGIS дают библиотеку и SQL-скрипты расширения. Ограничение `3.6.*` сохраняет нужную ветку версии.
- `&&` запускает следующую команду после успешной предыдущей.
- `rm -rf /var/lib/apt/lists/*` удаляет временные списки пакетов внутри создаваемого образа, уменьшая его размер.

Отдельный `start.sh` не нужен: команды запуска уже заданы в образе PostgreSQL и в Dockerfile backend.

### Nginx

- `listen 80` — порт внутри контейнера; `root` и `index` — папка и стартовый файл сайта.
- `resolver 127.0.0.11` — встроенный DNS Docker для поиска backend после пересоздания контейнера.
- `$api` — внутренний адрес backend, `$request_uri` — исходный путь вместе с параметрами.
- `location /api/` направляет запросы API в backend, сохраняя префикс `/api/v1`.
- Второй `location` передаёт документацию и проверки `/health/...`.
- `location /` с `try_files` отдаёт существующие файлы, иначе 404.
- `Cache-Control: no-cache` заставляет браузер проверять актуальность файлов после обновления проекта.

## 5. Управление приложением

Выполняйте команды из папки с `compose.yml`; на Ubuntu при необходимости добавляйте `sudo` перед `docker`.

```bash
docker compose ps                    # состояния контейнеров
docker compose logs --tail=100       # последние сообщения
docker compose logs -f backend       # наблюдать логи; Ctrl+C завершает просмотр
docker compose stop                 # остановить, сохранив контейнеры и данные
docker compose up -d                # снова запустить
docker compose restart frontend     # перечитать конфиг Nginx
docker compose down                 # удалить контейнеры и сеть, сохранив volume
```

Обновление из GitHub на Ubuntu:

```bash
git pull --ff-only
sudo docker compose up -d --build
sudo docker compose restart frontend
```

`--ff-only` не создаёт случайное слияние с локальными изменениями. `--build` пересобирает образы.
Перезапуск Nginx нужен при изменении `default.conf`; изменения HTML/CSS/JS видны после обновления страницы.
`docker compose down -v` удаляет также базу. Для обычной остановки эта команда не нужна.
Seed добавляется в пустую базу один раз, повторный запуск его не дублирует.

Для другого порта скопируйте `.env.example` в `.env`, измените `HTTP_PORT=8083` и выполните `docker compose up -d`.
`.env` исключён из Git. Изменение `DB_PASSWORD` после создания volume само по себе не меняет пароль уже существующего пользователя БД.
Предыдущий проект на 8081 и обычный Nginx на 80 могут продолжать работать.

## 6. Проверки

```bash
docker compose config -q
docker compose ps
curl -f http://localhost:8082/health/ready
curl -f 'http://localhost:8082/api/v1/events?page_size=1&include=venue,artist'
```

Если сайт не открывается с Mac, сначала проверьте `curl` на Ubuntu, её текущий IP и сеть виртуальной машины.
Если порт занят, задайте другой `HTTP_PORT`. Если база/API не готовы: `docker compose logs --tail=100 db backend`.

### Ошибка пользователя или пароля PostgreSQL

`.env` для запуска не обязателен. `POSTGRES_USER: postgres` и `PG_USER_NAME: postgres` уже заданы в Compose.
Обе настройки пароля используют `${DB_PASSWORD:-lab3-local-password}`: если переменной нет или она пуста,
Compose подставляет учебный пароль. Непустое значение можно передать из окружения терминала или `.env`.

`POSTGRES_PASSWORD` устанавливает пароль при создании **пустой** базы. Если volume уже содержит базу,
переменная не заменяет сохранённый пароль. Поэтому новые значения в обоих контейнерах могут совпадать,
но вход всё равно будет отклонён старой базой. В логах часто соседствуют `Skipping initialization`
и `password authentication failed for user "postgres"`.
Сообщение `role "postgres" does not exist` означает, что в подключённой базе нет такой роли.
Установленный отдельно на Windows PostgreSQL не участвует: backend обращается к сервису `db` в Docker-сети.

Посмотреть ошибки без вывода паролей:

```bash
docker compose ps -a
docker compose logs --tail=80 db backend
```

Для проверки с отдельной новой базой можно выбрать ещё не использовавшееся имя проекта:

```bash
docker compose -p microvolnovkkka-lab3-check up -d --build
docker compose -p microvolnovkkka-lab3-check ps
```

Все последующие команды для этой проверки также запускаются с тем же `-p`.
Если 8082 уже занят, сначала остановите именно прежний экземпляр приложения или выберите другой `HTTP_PORT`.
Повторное использование уже существующего имени проекта повторно подключит его volume.
Не удаляйте volumes других работ и не используйте `docker system prune --volumes` для исправления этой ошибки.

### Обновление с первой версии проекта

В первой версии имя проекта по умолчанию было `mpei-devops-lab3`, теперь — `microvolnovkkka-lab3`.
Если у вас работает именно старая версия, остановите её перед запуском новой:

```bash
docker compose -p mpei-devops-lab3 stop
docker compose up -d --build
```

Эти команды не удаляют прежний volume `mpei-devops-lab3_postgres_data`.
Новая версия использует отдельную базу с демонстрационными данными. Если в старой базе есть нужные изменения,
сначала сохраните её дамп и перенесите данные отдельно; смена имени проекта не является переносом базы.

Автоматические тесты на машине с Node.js 20+ (без `npm install`):

```bash
node --test tests/*.test.js
```

Проверяются порядок и состав столбцов, русские строки, кавычки, переносы, нулевая цена,
отсутствующие данные, защита от формул, выключенный заголовок и параметры API.
Ручная проверка: выбрать события на двух страницах, сменить фильтр, открыть «Выбранные»,
убрать и переставить столбцы, скачать CSV и сравнить с предпросмотром.
